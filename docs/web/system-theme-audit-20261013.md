# System theme candidate — October 13, 2026

Draft preparation only; no theme release is authorized. The system preference selects a curated light/dark web palette without adding an app override. Navigation icons and external-link marks use currentColor SVG; accessible names and link policy remain unchanged. Text-field boundaries and selected navigation/tab indicators are explicit. Dark map controls/popup text are themed while imagery, route strokes and semantic map colors stay unchanged. The manifest, identity, routing, data/provider/storage/access policies are unchanged.

The v40 browser baseline painted the same light palette in system light and dark. Its navigation label contrast was at least10.146:1; the reported barely visible Android system Back/Home/Overview was independently observed on an old installed native0.1.0 APK, not reproduced as web navigation text. The web changes are a separate presentation candidate, not a claim to fix Android native system bars.

Tests use the actual Kotlin router with fixture coordinates. Chromium and WebKit cover light/dark, portrait390x844100%, landscape640x320150%, narrow320x640200%, all main screens/chooser, preview/Directions/Share, and adapter-fed waiting/live/lost guidance. Axe checks regular text contrast; incomplete results and screenshots are retained for manual assessment. Navigation selection, keyboard focus, hover, and system toggling on a real preview are checked separately. Viewport simulation and simulated device GPS do not establish physical Android/iPhone GPS, installed-PWA OS chrome, screen-reader acceptance or full WCAG compliance. No app theme override exists. Disabled-control exceptions and map/canvas semantics require contextual assessment rather than a blanket numerical claim.

Primary standards: [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) (4.5:1 regular text,3:1 large text); [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) (3:1 information needed to identify enabled controls/states); [CSS color adjustment](https://www.w3.org/TR/css-color-adjust-1/#color-scheme-prop).

Map attribution now remains an explicit opaque dark-on-light pair in both schemes, regardless of lazy map CSS order. Zoom focus/tap, pressed presets, forced-color focused selection, and standalone-adapter chooser/input/Help states are checked. The themed browser theme-color metadata changes supported browser/PWA chrome, but not native Android activity bars. MapLibre toolbar icon inversion affects compass chrome; original route colors and connection-number map markers are retained. Original harness failures (transparent body measurement, shared output collision, browser-library lookup) and the real attribution defect are retained with corrected runs; no full certification is claimed.
