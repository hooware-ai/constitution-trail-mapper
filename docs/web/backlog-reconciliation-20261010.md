## Distance semantics correction in PR125

`TrailRouteTurnInstructionSijko.instructionsFor` emits distance **since the previous instruction**, resetting its accumulator after each emitted maneuver. `WebRoutingBridge.instructionJson` passes that value through unchanged. The core navigation snapshot accumulates those leg distances to resolve route-order positions. The web's original `instruction.distance` label, `mi from start`, incorrectly treated each leg as cumulative: the real 4.9-mile fixture loop's final leg displayed as 1.4 mi from start.

[PR125](https://github.com/hooware-ai/constitution-trail-mapper/pull/125) implements the presentation correction. It computes cumulative distance from the emitted legs and shows distance to the next step from the next emitted leg. It preserves instruction text/order/points and all route, closure, admission and navigation behavior; the itinerary remains a static plan, not a live GPS-distance display. The multi-instruction real loop reproduced the old label failure; its corrected and reversed itineraries pass the total/next-leg/accessible-description controls in Chromium and WebKit. Local engine and actual-county artifact controls passed for point-route selection/restoration, read-only navigation, short large text and strict gap Start/resume blocking. PR125 tracks the exact-head hosted gates and artifact/live verification status and results. Final-head gates and artifact verification must pass before release; anonymous live verification follows authorized publication. Invalid distances remain unavailable instead of becoming invented values.
