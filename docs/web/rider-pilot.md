# Voluntary rider feedback

This is preparation for #72, not collected demand evidence. The existing Site is now public at https://constitution-trail-mapper.hooware.chatgpt.site under Jesse’s [October 9 launch decision](public-launch-20261009.md). This checklist does not authorize recruitment or outbound messages. No analytics, visitor identifier or automatic GPS/history upload is part of the feedback flow.

Use the exact authorized release and record its build, data version and origin from Help. Record the browser/device only if the rider chooses to share it. Automated mobile emulation and simulated fixes do not establish physical GPS or outdoor acceptance.

Ask the rider to try only the tasks supported by that release:

- Find an appropriate point route or exercise loop without an account.
- Explain what the closure, shared-roadway and estimated-access warnings mean before deciding whether to Start. Check official notices and physical signs; an estimated end is not reopening.
- Save intentionally, leave the planner, and reopen the save in the same browser. Current saves are browser-local; sign-in and cross-browser sync are unavailable.
- If they choose to try foreground guidance, keep the page open and visible. Record planning, starting guidance and actually riding as separate outcomes. Do not count an opened route as a completed ride.
- Reopen Help and choose **Write ride feedback**. Review/edit the template, then copy it only if they want to share it. No feedback is submitted by the app. The existing issue-form link is public and requires a GitHub account; do not include private locations, geometry, saved names or personal details.

For each task, record only voluntary success, partial success, failure or not tried, with a concrete obstacle. Ask whether this was a first or return visit, why they returned, what the app prevented them from doing, and what would make it useful again. A rider's report is self-reported evidence, not a measured GPS trace or population-level adoption result.

Keep web defects distinct from unmet native needs such as dependable locked-screen guidance, offline downloads or sensors. Do not promise those features or start native work. File a deduplicated defect with a synthetic/minimized reproduction. Publish only sanitized summaries of consented feedback, including the sample size and limitations. Jesse decides whether repeat-use evidence justifies native investment; no adoption threshold is invented here.
